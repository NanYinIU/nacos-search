# Keep one persisted environment model and edit intents, not profiles

Environment configuration is persisted as environment profiles plus profile-associated preferences. `servers`, `activeServerId`, and the flat endpoint/authentication fields remain public mutable beans only so IntelliJ XML serialization can read settings written by previous releases. Their constructor defaults are empty. `loadState` passes them to the versioned migrator, which consumes them only for a pre-CURRENT schema and then clears them; a CURRENT state ignores stale compatibility values. `getState` clears them on its persisted snapshot. No runtime, Settings Apply, reset, or environment-selection path reads or writes them.

The settings dialog edits **profile intents**: user-chosen attributes without profile revision, access revision, or credential-slot identity. `EnvironmentProfileStore` is the sole publisher. It compares each intent with the published profile, stages any required immutable credential slot before publication, and derives both revisions and the slot coordinate. Stage failure and deletion-tombstone failure remain fail-closed. Suggested Namespace and preference records stay associated with the profile without entering its access identity.

Opening, cancelling, and resetting the dialog operate on `SettingsIntentDraft` only. Apply publishes intents but does not change the migration-owned default or any project's selection. The Settings blue dot prefers the project session and otherwise uses the migration default. Runtime preference reads use the project-selected profile, or the migration default only when no project session is available. This keeps project selection local and keeps every Swing/PSI identity read credential-free.
