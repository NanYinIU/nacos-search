# Judge paintability by session epoch, configuration coordinate, and observation sequence

An asynchronous result may update what the tool window presents only when its session epoch equals the current one, its configuration coordinate equals the one currently selected, and its observation sequence is not older than the last one painted. This is deliberately the same shape as the observation high-water that orders cache mutations — one mechanism with a correctly scoped key — rather than the three incompatible mechanisms in place today: a panel-local counter inlined at seven sites, a comparison of profile id and namespace id in the tool window, and the project session epoch in the history dialog.

None of the three parts is new. The session epoch already exists and already advances on environment, namespace, profile-revision, access-revision, and resolved-generation changes; the configuration coordinate already identifies what is selected; and the observation sequence is already taken when a remote operation starts. The panel-local counter was reinventing the third of these with a narrower scope, and it is deleted. The one addition is that a gateway read returns the observation sequence it took, so a caller that paints a result can order it by the same number that orders the cache write derived from the same observation — two consumers of one observation, not two coincidentally similar counters.
