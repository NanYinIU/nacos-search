# Collapse cache writes into one gated entry point

The cache module exposes a single write operation taking a cache mutation together with its observation sequence, so the cache-entry gate's scope equals the mutation's coordinate by construction and no write reaches the store without passing it (ADR-0044). Reads stay named operations returning their own types: the argument for collapsing writes is that the gate must be unbypassable, reads have no such property, and forcing symmetry would trade readability for nothing. Six named write methods each calling a private gate was rejected because that arrangement has already failed twice inside this very module — fourteen of sixteen cache mutation call sites carry no observation sequence at all, and of the four identity-scoped writers that must consult the profile-deletion tombstone, one was written without it. A user's explicit cache clear is a mutation and takes a sequence, so a write that started before the clear loses to it while an operation started afterwards lands normally; by contrast the cache reconstituting an entry from its own persistent store is not a mutation and stays private behind the read path, which is where a lazy single-key load could previously resurrect an entry the user had just cleared. The cache also hands out a versioned snapshot carrying its own version and as-of instant, replacing the modification counter, clock, and coroutine scope it currently lends to callers that cache a derivation of it.
