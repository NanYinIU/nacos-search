# Make cache writes unreachable outside the operation layer

The cache module's write surface — the cache mutation type and the single gated write entry point ADR-0045 collapsed it into — carries an opt-in requirement, so naming either one from the UI layer or the code-navigation layer is a compile error rather than something review has to notice. "No module outside the operation layer writes to the cache" is an architecture-fitness property, not a behaviour, so it is enforced by the compiler and not by a test; a test would assert the current call sites rather than the property, and this module's history is that conventions about who must remember what fail here. ADR-0045 made the gate unbypassable *once a caller reaches it*; this closes the remaining half, which is who may reach it at all.

The layering is not arbitrary. An observation sequence is taken when a remote operation starts, and only the layer that performed the operation holds one, so a panel or a gutter renderer that wants to write has nothing correct to pass: it can restamp what the gateway already wrote under the same sequence — which the high-water rejects anyway — or it can invent a sequence and lock out a genuine read that started earlier. Both were live in this codebase. Reads carry no such requirement: the UI and code-navigation layers read the cache freely, including the snapshot the derived key index is built from.

A Kotlin opt-in marker was chosen over the alternatives available in a single Gradle module. Package-private visibility does not exist in Kotlin, `internal` is module-wide and therefore no boundary at all here, and splitting the cache and operation layers into their own Gradle subprojects would restructure the build for a slice that adds no runtime logic. The marker's escape hatch is explicit and greppable: opting in is a deliberate act on a named declaration, and it belongs to the operation layer in two forms — components that perform remote operations (the gateway's cache adapter, the namespace index coordinator, the navigation detail prefetch, the API service's clear gestures) and the recorder that turns a completed operation's observation into a mutation on its caller's behalf. The cache module's own tests opt in too.

That recorder is the shape the displaced writer takes. The configuration detail panel deleted a cached detail on an authoritative not-found; it now hands the recorder what the read observed, together with the sequence that read took, and holds no cache mutation. It still decides *when* to report — moving that decision out of the Swing panels is separate work.

The gutter marker's write was kept at the time rather than deleted as a duplicate of the gateway's, because it looked like one and was not: an AUTO-policy profile resolves its API generation per operation, so the gateway wrote under an identity carrying V1 or V3, while the code-navigation hot path derived its identity without touching the credential store and therefore left the generation UNKNOWN. The resolved generation is part of the cache key, so the two landed in different key spaces, and the one the gutter read was populated by that write alone. Making the write unreachable would have silently turned it into a missing gutter marker.

That divergence has since been closed. ADR-0053 gives the hot path the resolved generation from the project session and the persisted last-known value, both credential-free, so one environment addresses one key space on every path. The gutter marker's write is a genuine duplicate under that rule and is gone; `@NacosValue` navigation now records no configuration detail, and the recorder's only remaining caller is the detail panel's authoritative not-found.
