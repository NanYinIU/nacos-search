# Keep the navigation detail prefetch toggle out of the environment profile

The navigation detail prefetch toggle is a per-environment preference stored in a **profile-associated preference record** (keyed by environment profile id, no connection target or derived revisions) and published through the preference-only settings notification, not a field of the environment profile. Placing it on the profile would bump the profile revision, which ADR-0010 makes a session-epoch trigger, so turning a background prefetch off would cancel in-flight browsing and force a fresh API-generation detection — a cost out of all proportion to a toggle whose failure, per ADR-0041, lowers only code-reference decidability and never namespace-index completeness or content-search coverage. Write intent stays on the profile because it gates which operations are permitted and therefore belongs to the profile's capability contract, whereas this toggle governs cost; its closest precedent is the cross-namespace navigation toggle, already a per-environment preference over the same code-navigation subsystem and the same preference record. The consequence is that the prefetch reads its toggle at trigger time from that record rather than receiving it inside the captured operation context, so the prefetch is responsible for observing cancellation itself rather than being protected from mid-operation retargeting the way a profile-captured setting would be. Keeping preferences off the profile and off the legacy server list as a runtime source reconciles this decision with ADR-0049 (one persisted environment model).
