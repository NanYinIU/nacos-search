# Trigger the navigation detail prefetch independently of namespace indexing

The navigation detail prefetch is its own flight with its own freshness gate, keyed by access identity and project, rather than a continuation of namespace indexing; its results still enter the identity-scoped detail cache at the ordinary configuration coordinate, so two projects on the same access identity share whatever either has already fetched. Chaining it to index completion was rejected because the prefetch's work set is bounded by the declared configuration sources — a per-project signal — while namespace indexing is keyed by access identity and namespace: half the index triggers, including startup preheat and manual cache refresh, carry no project at all, so a chained prefetch would either contribute nothing to gutter markers on exactly the path whose purpose is to make them instant, or fan detail requests out across every open project, contradicting ADR-0041's rule that prefetch cost scales with what the code references rather than with namespace size. A chained prefetch would also inherit the namespace index's freshness check, under which a data id newly declared in the project stays unresolved until the index TTL expires, because after ADR-0041 a fresh index no longer implies the declared sources' details are cached. Keeping the flights separate additionally keeps ADR-0041's failure isolation and ADR-0020's per-operation observation sequence structural rather than dependent on discipline at one call site.
